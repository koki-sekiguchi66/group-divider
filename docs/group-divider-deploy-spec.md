# グループ分け Web アプリ（V3）— 実装＆デプロイ ドキュメント（完全無料運用）

## 0. このドキュメントについて

- 既存の単一HTML（vanilla JS・依存ゼロ）をベースに、**(1) 完全無料でのWebアプリ公開**、**(2) オーナーが事前にメンバー登録 → 担当者はチェックイン・班分け・共有だけで完結**、という運用を実現するための更新版。
- 別チャット／別環境にそのまま渡して実装・デプロイできる粒度で記述。バックエンド不要・過剰設計不要。

---

## 1. 運用フロー（役割分担）

```
[オーナー(あなた)]
  事前にメンバーを登録（名前＋性別＋幹部）
      ↓ 「共有リンクを発行」ボタン
  メンバー入りのURLが生成される
      ↓ LINEで送付
[担当者]
  リンクを開く → メンバーが自動で入った状態に
      ↓
  当日：チェックイン（出欠）→ 班分け実行 → 結果をLINEグループへ共有
```

- オーナーはアプリ上でメンバーを登録するだけ（コード編集不要）。
- 担当者は受け取ったURLを開くだけで、登録済みメンバーがそろっている。
- チェックイン状態・班分け結果は担当者の端末（localStorage）に保存される。

---

## 2. データ受け渡し設計（最重要・ここが構成の核）

静的ホスティング＋localStorage は**端末ごとに独立**するため、「オーナーが登録 → 担当者の端末に届ける」方法を決める必要がある。完全無料（バックエンドなし）で実現できる方式は次の通り。

### ▶ 方式A：共有リンク（**推奨**）
- オーナーが登録 → **メンバー情報をURLに埋め込んだ共有リンク**を発行 → LINEで担当者へ。
- 担当者がリンクを開くと、メンバーが自動で読み込まれ localStorage に保存される。
- **完全無料・バックエンド不要・端末をまたげる・コード編集不要。**
- 注意：メンバーを後から変えたら、リンクを再発行して送り直す（イベント前の確定運用なら問題なし）。

### 方式B：ソースに直書き（開発者向けの代替）
- `members.js` にメンバー配列をハードコードしてデプロイ。担当者は**固定URLを開くだけ**で常にメンバーがそろう（最もシンプル）。
- 変更時は `members.js` を編集して再デプロイ（開発者なら数分）。

### 方式C：無料バックエンド（今回は非推奨）
- Firebase / Supabase の無料枠でリアルタイム共有も可能だが、設定が増えるため本件では不要。

> **結論：方式A を採用**（柔軟・無料・コード編集不要）。開発者として固定URLにしたい場合のみ方式B。

### 2.1 共有リンクの技術仕様（方式A）

- メンバー配列をコンパクト化 → **UTF-8安全なBase64** に変換 → **URLハッシュ**（`#d=...`）に格納。
- ハッシュにする理由：サーバーに送信されず、純粋にクライアントで完結するため。
- 日本語名があるので `btoa` を直接使うと壊れる。下記のUTF-8経由の変換を必ず使う。

```js
// ---- エンコード（オーナー側：共有リンク発行）----
function encodeMembers(members){
  // 名前/性別/幹部 だけを配列で持たせて短くする（checkedIn は含めない）
  const compact = members.map(m => [m.name, m.gender, m.core ? 1 : 0]);
  const json = JSON.stringify(compact);
  const bytes = new TextEncoder().encode(json);          // UTF-8 → bytes
  let bin = ''; bytes.forEach(b => bin += String.fromCharCode(b));
  return btoa(bin);                                      // → Base64
}
function makeShareUrl(members){
  const base = location.origin + location.pathname;      // 例 https://xxx.pages.dev/
  return base + '#d=' + encodeURIComponent(encodeMembers(members));
}

// ---- デコード（担当者側：リンクを開いたとき）----
function decodeMembers(b64){
  const bin = atob(b64);
  const bytes = Uint8Array.from(bin, c => c.charCodeAt(0));
  const json = new TextDecoder().decode(bytes);          // bytes → UTF-8
  return JSON.parse(json).map(a => ({
    id: uid(), name: a[0], gender: a[1], core: !!a[2], checkedIn: false
  }));
}

// 起動時：ハッシュにメンバーがあれば取り込む
function importFromHashIfAny(){
  const h = location.hash;
  if (h.startsWith('#d=')) {
    try {
      const imported = decodeMembers(decodeURIComponent(h.slice(3)));
      if (confirm(`${imported.length}人のメンバーを読み込みます。よろしいですか？\n（現在の登録は置き換わります）`)) {
        state.members = imported;
        saveM(state.members);
      }
    } catch(e) { alert('リンクの読み込みに失敗しました'); }
    history.replaceState(null, '', location.pathname);   // ハッシュを消してURLをきれいに
  }
}
```

- 取り込み後はlocalStorageに保存されるので、担当者は**2回目以降はリンク不要**（同じ端末で開けばよい）。

## 4. 機能要件（更新版）

画面は3つ：**登録（オーナー用）／チェックイン／グループ分け**。

### F1. メンバー登録（オーナー用）
- 名前＋性別（男/女）＋幹部フラグで追加。
- 一覧表示し、**名前の編集**・幹部ON/OFF・削除ができる。
  - 名前編集：行の「✏️編集」をタップ → 名前がテキスト入力に変わる → 保存で `member.name` 更新＆localStorage保存（性別・幹部も編集可にしてよい）。
- localStorage に保存。

### F2. 共有リンク（方式A）
- 登録画面に **「🔗 共有リンクを発行」** ボタン → `makeShareUrl()` でURL生成 → クリップボードへコピー（またはWeb Share APIで共有）。
- 起動時に `importFromHashIfAny()` を実行（リンク経由なら自動取り込み）。

### F3. チェックイン
- 登録メンバー一覧をタップで「来た/まだ」をトグル。来場/未到着のカウント（任意で男女内訳）を表示。
- 「全員リセット」あり。状態は localStorage 保存。
- 班分けの対象は**チェックイン済みメンバーのみ**。

### F4. 班数設定
- 既定3、2〜7。チェックイン人数から定員プレビュー（例 15人/3班 → `5・5・5`）。

### F5. モード選択 ＋ 実行（**ここがUI修正点**）
- **モードは「選択状態」を持つ**：`selectedMode = 'random' | 'core'`（既定 'random'）。
- 2つのモードボタンを**セグメント切替**として表示：
  - 選択中＝塗りつぶし（例：緑背景＋白文字）、未選択＝アウトライン（白背景＋グレー）。
  - タップで `selectedMode` を切替 → **再描画で色が変わる**（現状の不具合を解消）。
- **男女均等トグル**（ON/OFF）はそのまま。
- 別途 **「▶ グループ分け実行」** ボタンを置き、押下時に `selectedMode` ＋ 男女均等設定で `divide()` を実行。
- 「🔄 再シャッフル」「📋 結果をコピー」も継続。

### F6. 結果表示
- 班ごとにカード表示（班番号・人数・男女内訳・メンバー）。画面上は幹部に印を付けてよい（共有テキストには出さない）。

### F7. 結果共有（LINE向け・★なし）
- 「結果をコピー」で下記テキストを生成し `navigator.clipboard.writeText()`。Web Share API があればそれも可。
- **幹部マーク（★）は付けない。** → 「5.」参照。

## 5. 共有テキスト仕様（LINEグループ貼り付け用）

- 班が一目で分かること・★を付けないこと、が要件。フォーマット例：

```
【グループ分け】

▼ 1班（5人）
田中
佐藤
高橋
中村
小林

▼ 2班（5人）
鈴木
渡辺
加藤
吉田
山口

▼ 3班（5人）
…
```

- 生成コード（★なし）：
```js
function buildShareText(teams){
  return '【グループ分け】\n\n' + teams.map((t, i) =>
    `▼ ${i+1}班（${t.length}人）\n` + t.map(m => m.name).join('\n')
  ).join('\n\n');
}
```
- 男女内訳を入れたい場合はヘッダーを `▼ 1班（5人 / 男3 女2）` にしてよい（任意）。**幹部表記は入れない。**

## 6. 班分けアルゴリズム（前版から不変）

`shuffle / teamSizes / divide(members, teamCount, {useCore, balanceGender})` をそのまま使用（純粋関数）。要点：

- `teamSizes(15,3) -> [5,5,5]`、`teamSizes(14,3) -> [5,5,4]`。
- 幹部分散：幹部をラウンドロビンで各班へ均等配置 → 残りを配置。
- 男女均等：残りを「その性別が最も少ない班」へ詰めて均等化。
- 不変条件：各メンバーは1班のみ／班サイズ合計＝対象人数／サイズ差は最大1。

（詳細擬似コードは前ドキュメント「アルゴリズム仕様」と同一。変更なし。）

## 7. デプロイ手順（完全無料）

単一の静的ファイル（`index.html`）なので、無料の静的ホスティングに置くだけ。**サーバー費用・独自ドメインとも不要**（`*.pages.dev` 等の無料URLで運用可）。

### 推奨：Cloudflare Pages
- 無料プランでも静的アセットへのリクエストと帯域が無制限で、月500回のビルドが使え、静的サイトを無料公開したい初心者にかなり有力。
- リポジトリが Private でも公開でき、GitHub連携もスムーズ（ダッシュボードでGUI設定が完結）。
- 手順：GitHubに `index.html` をpush → Cloudflareダッシュボード → Pages → リポジトリ連携 → デプロイ → `https://<project>.pages.dev` が発行される。

### 最も手軽：Netlify Drop（アカウントなしで試せる）
- 管理画面が分かりやすく初心者向け。`index.html` を含むフォルダを app.netlify.com/drop にドラッグ＆ドロップするだけで即URL発行。Gitすら不要。

### GitHub Pages（公開リポジトリでよければ）
- 公開サイトは1GBまで、帯域は100GB/月のソフト制限。とにかくシンプルに公開したい人向け。無料プランでは Public リポジトリにする必要がある（中身が公開される）点だけ留意。
- 手順：リポジトリ作成 → `index.html` をpush → Settings → Pages → ブランチを指定 → `https://<user>.github.io/<repo>/`。

> 個人情報（メンバー名）を含むため、ソースを公開したくない場合は **Cloudflare Pages（Private可）** か **Netlify Drop** が無難。GitHub Pages無料はソース公開になる点に注意。なお方式A（共有リンク）ならメンバー名はソースに入れず、URL（自分とLINE相手だけが持つ）に載るだけなので、どのホスティングでもソースは汎用テンプレのままにできる。

## 9. 技術メモ

- **依存ゼロのvanilla JS＋単一HTML**を維持（ビルド不要・オフライン動作）。
- 状態は **localStorage**（メンバー＋チェックイン）。メンバー受け渡しは **URLハッシュ**（方式A）。
- 日本語名のBase64は **TextEncoder/TextDecoder 経由**で行う（`btoa` 直叩きはNG）。「2.1」参照。
- 個人情報をソースに残したくない → 方式A＋Cloudflare Pages/Netlify。
- これはイベント1回限りの用途。高可用性・拡張性は不要。
